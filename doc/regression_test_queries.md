# 기능 확인용 질문 목록

서비스 기능을 확인할 때 사용하는 예시입니다. 답변은 실제 조회한 대상·수치·
대응 문서와 일치해야 하며, 확인하지 않은 내용을 관측 사실로 표현하지 않습니다.
실행 방법은 [서비스 README](README.md)를 참조합니다.

| 번호 | 질문 | 확인할 동작 |
|---|---|---|
| 1 | payments-service 결제 응답이 느려지고 CPU가 치솟았어요, 원인 확인해주세요 | 결제 서비스 조회, 관측값 확인, 증상에 맞는 대응 절차 |
| 2 | cache-service 메모리 사용률이 계속 올라가고 있어요 | 캐시 서비스 조회, 메모리 증상과 대응 문서 연결 |
| 3 | log-service 디스크 공간이 부족하다는 알림이 왔어요 | 로그 서비스 조회, 디스크 알림과 대응 문서 연결 |
| 4 | gateway-service에서 payments-service로 가는 요청이 타임아웃 나고 있어요 | 요청한 두 서비스 모두 조사, 확인 가능한 호출 경로 증상 설명 |
| 5 | web-01 CPU 급증, auth-service 커넥션 풀도 같이 확인해줘 | 두 대상 조회, 실제 지표에 따라 증상 확인 여부 구분 |
| 6 | payments-service랑 cache-service 둘 다 저하됐는데 공통 원인이 있는지 분석해줘 | 두 대상 조사, 서비스별 대응 문서 확인, 공통 원인은 근거 범위에서 추정 |
| 7 | 로그인 응답이 느려요, 원인 확인해주세요 | 확정된 이전 대상이 없으면 대상 확인 질문 |
| 8 | billing-service 응답이 느려요 | 미등록 대상 안내, 다른 서비스로 임의 대체하지 않음 |
| 9 | 안녕, 너는 누구야? | 일반 대화 응답, 불필요한 장애 조사 없음 |
| 10 | 제 이름은 민수입니다 → 제 이름이 뭐였죠? | 같은 대화의 정보 기억, 서로 다른 대화의 정보 분리 |

## 후속 대화와 화면 확인

- payments-service를 조사한 후 “그 서비스의 메모리도 확인해줘”라고 요청합니다.
  실제 조회 대상이 payments-service인지 확인합니다.
- 앞서 여러 서비스를 조사했다면 단수 지칭을 임의로 하나에 연결하지 않습니다.
- 명시적으로 새 대상을 지정하면 그 대상을 우선합니다.
- “현재 상태”, “다시 확인”은 새로 조회한 값과 조회 시각으로 답합니다.
- 같은 대화 ID의 대화 복원과 새 대화의 정보 분리를 확인합니다.
- 도구 실패·자료 부족·검증 미달을 완료 또는 검증 통과와 구별합니다.

기능별 자동 테스트는 각 구현 모듈과 함께 추가합니다.
