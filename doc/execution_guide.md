# OpenAI 실행·통합 확인 가이드

서비스 폴더에서 실행한다. Python 3.11과 로컬 단일 서버 프로세스를 기준으로 한다. 데이터는 가상 서비스 모니터링과 예제 런북이며 실제 시스템 조치 기능은 없다.

## 1. 환경 준비

처음 준비할 때만 실행한다. 이미 있는 가상환경은 그대로 사용한다.

```bash
bash sh/setup_venv.sh
```

`.env`가 없으면 `.env.example`을 복사하고 본인 키를 입력한다. 기존 `.env`는 덮어쓰지 않는다.

```bash
cp -n .env.example .env
```

필수 설정은 [런북 검색 가이드](runbook_search.md)의 설정 예를 따른다. OpenAI API는 사용량에 따라 과금된다. 키를 로그·저장소·화면에 넣지 않는다. `gpt-4o-mini`, `gpt-4o`, `text-embedding-3-small` 접근 권한이 필요하다.

## 2. 기능 테스트와 인덱스

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python sh/build_runbook_index.py
```

기능 테스트는 유료 API를 호출하지 않는다. 인덱스 최초 생성·변경 문서 처리에는 임베딩 API를 사용한다. 그대로인 문서는 재사용한다. 검색 요청은 누락·오래된 인덱스를 자동 재생성하지 않는다.

## 3. 서버 실행

터미널 A:

```bash
bash sh/run_agent_openai.sh
```

터미널 B:

```bash
bash sh/run_frontend.sh
```

`http://localhost:8600`에서 사용한다. 각각 Ctrl+C로 종료한다. 포트 8100/8600이 사용 중이면 스크립트가 중단하므로 해당 서버를 직접 확인한다. 다른 프로세스를 자동 종료하지 않는다.

```bash
curl -fsS http://127.0.0.1:8100/health
```

`llm_backend=openai`, `supervisor_version=v2`를 확인한다. 실행 스크립트는 외부 추적을 끈다.

대화는 기본 `session.db`에 저장한다. 시험용 DB가 필요하면 `.env`의 `SESSION_DB_PATH`를 전용 경로로 설정한다. 기존 DB를 삭제할 필요는 없다. 서버 재시작 때 같은 DB 경로를 사용한다.

## 4. 순서대로 전체 기능 확인

| 순서 | 입력·행동 | 기대 동작 |
|---|---|---|
| 1 | 새 대화 → 메모리가 계속 증가해요. 상태와 대응 절차를 확인해줘 | 대상 확인 질문, 임의 서비스 조사 없음 |
| 2 | cache-service | 캐시만 수집·검색, 관측 사실과 원문 인용 표시 |
| 3 | 지금은 정상화됐어? | 캐시의 새 관측 출처·수집 시각으로 재조사 |
| 4 | payments-service와 cache-service 상태와 대응 절차를 확인해줘 | 두 대상 모두 조사, 서비스별 런북 연결 |
| 5 | 그 서비스 다시 확인해줘 | 하나로 임의 선택하지 않고 대상 확인 |
| 6 | cache-service | 선택한 대상만 재조사 |
| 7 | 새로고침 | 저장된 답변·당시 상태 복원, 생성 호출 없음 |
| 8 | 백엔드 종료 후 동일 DB로 재실행 → 새로고침 | 메시지·처리 상태·후속 문맥 유지 |
| 9 | 새 대화 → 지금은 정상화됐어? | 이전 대상을 적용하지 않고 서비스 확인 |
| 10 | auth-service 말고 cache-service만 확인해줘 | 캐시만 조사 |
| 11 | billing-service 상태를 확인해줘 | 미등록 대상 안내, 다른 서비스로 대체 없음 |
| 12 | web-01 현재 상태를 확인해줘 | 정상·무알림 관측, 불필요한 런북 검색 생략 |

`사실·인용 대조 통과`는 관측값·출처·문서 인용 대조를 뜻한다. 런북 적합성과 원인 확정은 별개다. 가설은 미검증 추정이고 참고 절차는 실행 기록이 아니다. 과거 답변 복원은 현재 상태 재조사가 아니다.

POST `/chat`과 GET `/chat/stream`은 같은 `thread_id`에서 문맥을 공유한다. GET `/sessions/{thread_id}`는 저장된 이력과 메타데이터·문맥을 반환한다. 세부 상태는 [세션 가이드](session_continuity.md)와 [검색 가이드](runbook_search.md)를 따른다.

## 5. 문제 대응

| 현상 | 원인·대응 |
|---|---|
| 키·권한·할당량 오류 | `.env`와 API 계정 설정 확인. 오류를 정상 완료로 해석하지 않는다. |
| 검색 error | 인덱스·모델·차원·문서 변경 확인 후 인덱스 생성 명령 실행 |
| 검색 no_match | 관련 문서 미선택. 문서 적합성 검토가 필요하며 원인 확정 아님 |
| partial | 대상 미확인·관측 실패·검색 실패 등 메타데이터와 누락 항목 확인 |
| validation_failed | 최대 3회 대조 실패. 표시된 관측 사실만 사용하고 가설·조치 판단 보류 |
| 복원 오류·연결 중단 | 대화 다시 불러오기로 저장 여부 확인. 요청 자동 재전송 없음 |
| 새로고침 후 다른 대화 | 같은 탭·DB 경로 확인. 탭 종료·저장소 초기화 후 연결은 보장하지 않음 |

현재 범위는 로컬 데모다. 인증·권한, 여러 서버 프로세스 동시 처리, 장기 이력 페이지 분할, 대화 목록 UI, 모든 별칭·자연어 지칭 해석은 별도 확장이다. 측정된 토큰은 실제 usage이며 기존 `cost_usd`는 가상 단가 계산값으로 실제 청구액이 아니다.
